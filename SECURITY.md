# Security Policy

The [dileepadev](https://github.com/dileepadev/dileepadev) project team takes security issues very seriously. We appreciate your efforts to responsibly disclose any security vulnerabilities you find.

## Scope

This repository ships no application. It holds documentation, brand assets, and the canonical
token sheet — there is no build step, no dependency tree, no runtime, and no credential. A
security report here would concern the content itself: a document that leaks a real secret or an
internal hostname, an asset that carries unintended metadata, or a link that points somewhere it
should not.

Vulnerabilities in the applications this repository documents belong in those repositories:
[dileepa-dev](https://github.com/dileepadev/dileepa-dev),
[api-dileepa-dev](https://github.com/dileepadev/api-dileepa-dev),
[admin-dileepa-dev](https://github.com/dileepadev/admin-dileepa-dev),
[links-dileepa-dev](https://github.com/dileepadev/links-dileepa-dev),
[blog-dileepa-dev](https://github.com/dileepadev/blog-dileepa-dev), and
[dileepadev.github.io](https://github.com/dileepadev/dileepadev.github.io). If you are not sure
which repository is affected, report it here and it will be routed.

## Reporting a Vulnerability

If you discover a security vulnerability, please send an email to **<contact@dileepa.dev>**. Please do not create a public issue for the vulnerability.

Your email should include the following information:

- A description of the vulnerability
- Steps to reproduce the vulnerability
- Possible impact of the vulnerability
- Any suggested mitigation or remediation steps

We will respond to your email as soon as possible and work with you to address any security issues.

## Bug Bounty Program

At this time, we do not offer a bug bounty program. If we decide to introduce one in the future, details will be shared here.

## Maintainer Responsibilities

Maintainers are responsible for the security of the project. This includes:

- Responding to security reports in a timely manner
- Investigating reported vulnerabilities
- Developing and releasing patches for confirmed vulnerabilities
- Communicating with the reporting party as the issue is addressed
- Regularly reviewing and auditing the security of the project

## Disclosures

- We will acknowledge receipt of your report within one business day as soon as possible.
- We will confirm the vulnerability and determine its impact.
- We will release a fix as soon as possible, depending on the complexity of the issue.
- We will communicate the vulnerability and any patches or workarounds to our users.

Thank you for your help in making the [dileepadev](https://github.com/dileepadev/dileepadev) project a more secure place.
